# FDE 交付手册（fde-kit 配套）

这份手册不是技术文档，是**进场流程**。技术决定你能不能做出来，流程决定客户认不认。

## 一、七步交付法

### 第 1 步：先问“谁在什么场景下会问什么”（半天）

不要一上来要资料。先找 2～3 个真实使用者（客服、售后工程师、销售支持），
让他们各自写下**昨天真实回答过的 5 个问题**。这些问题就是你的验收集原型。

产出：15 条真实问题，标注“答错会怎样”。

### 第 2 步：写本体，不写代码（半天）

把上一步的问题拆成实体：他们嘴里反复出现的那几类东西（型号？故障码？合同号？批次？）。
每类给一个正则和一个别名表。

判断标准很简单：**如果一类实体在 15 个问题里出现不到 2 次，先别加。**
本体不是越全越好，是越准越好——加错了会在检索期给错误加权，比不加更糟。

### 第 3 步：只拿 20 份资料做第一版（半天）

不要一次导 3000 份。挑最核心的 20 份（政策、手册、FAQ、台账），跑：

```bash
FDE_CORPUS=/path/to/20docs fde compile --reset
```

看三个数字：分块数、失败数、实体覆盖。失败数不为 0 就先解决解析，别急着调检索。

### 第 4 步：10 条问题做基线（半天）

前 10 条真实问题写成 `evals/golden.yaml`，`must_cite` 填“答案必须出自哪份文档”，
`keywords` 填“必须出现的硬口径”（金额、时限、型号）。跑 `fde eval`。

**这一步最容易犯的错**：用例写得太宽松（比如 must_cite 只写“政策”两个字），
结果 hit@5 100%，自己骗自己。must_cite 要具体到能区分的程度。

### 第 5 步：看失败案例，不要看平均数（半天）

`fde eval` 输出的失败清单才是金矿。逐条判断属于哪一类：

| 现象 | 真实原因 | 该改什么 |
|---|---|---|
| 检索没召回 | 语料缺口 / 本体漏了实体 | 补资料，加实体类型 |
| 召回了但排第 4 | 切块太大，关键句被稀释 | 调 `target_tokens`，或按小节切 |
| 召回了但答非所问 | 压缩把关键句丢了 | 提高 `per_chunk_max_tokens` |
| 引用编号是假的 | 提示词约束不够 | 收紧系统提示词；verify 已有重试 |
| 该拒答却硬答 | 闸门阈值太松 | 提高 `FDE_MIN_COVERAGE` |

### 第 6 步：出报告，开验收会（1 小时）

```bash
fde report   # data/reports/latest.html
```

报告里有四样客户真正关心的东西：进来了什么、覆盖了什么、测得怎么样、哪里不行。
**主动把“未纳入的资料”和“未通过的用例”放在前面讲**，比藏起来可信得多。

### 第 7 步：留复用资产（持续）

交付结束时，把这次的本体、评测集、警告清单收进一个目录，命名为 `<客户>-<日期>`。
下一个客户从这里起步，通常能省掉 60% 的工作量。

## 二、验收口径（写进合同的语言）

- **有据可依率 ≥ 95%**：回答里至少有一处真实引用，且引用编号能在证据集中找到。
- **引用有效率 = 100%**：不允许出现证据集之外的 `[S#]`。这条是红线。
- **hit@k ≥ 90%**（k=5）：必答口径能在前 5 条证据里找到。
- **关键词覆盖率 ≥ 90%**：金额、时限、型号这类硬口径不能含糊。
- **反例题必须拒答**：库里没有的信息，系统必须说“没有”，不能编。

注意这些指标**都不依赖 LLM 打分**，所以在客户内网、无外网的环境也能复现。
这是刻意设计的：验收标准必须可重复执行，否则就是口水仗。

## 三、现场常见坑

**坑 1：客户给的“最新版”其实是三年前的。**
编译后看 `assets` 的修改时间，和客户确认哪份为准。同一份政策多个版本同时进库，
检索会随机命中旧版——这是最危险的错误类型，因为它看起来完全正常。

**坑 2：扫描件 PDF。**
没有文本层，`parse_pdf` 会返回空文本并记 warning。不要试图用 RAG 解决 OCR 问题，
要么让客户提供原始文档，要么单独接 OCR，别混在检索链路里。

**坑 3：Excel 里的合并单元格。**
导出成 CSV 后，合并单元格只有第一行有值，其余为空。
这会让“某型号属于某客户”这类关系丢失。要么让客户补全，要么在导入前用脚本填充。

**坑 4：客户想让你“顺便”接他们的工单系统。**
先别接。用导出的 CSV 跑通闭环、拿到验收数字，再谈实时接口。
反过来做，你会花两周在权限和 VPN 上，而闭环还没验证过。

**坑 5：以为换个更强的模型就能解决召回问题。**
召回不行换模型没用。判断方法：`fde search` 看证据里到底有没有正确答案。
没有 → 语料/切块问题；有但排第 8 → 检索融合问题；有且排第 1 但答错 → 才是模型问题。

## 四、一句话总结

> 交付的不是一个能聊天的页面，是一份**能被复核的证据链**。
> 模型可以换，证据链不能断。
